# 業務ガイド（Chrome 拡張機能）

業務Webシステムの画面の上に、操作手順のガイドを重ねて表示する Chrome 拡張機能です。
**ビルド不要**：このフォルダをそのまま Chrome に読み込めば動きます（Node.js も npm も使いません）。

| 機能 | 内容 |
|---|---|
| ガイド付きツアー | JSON で書いた手順に沿って、画面の要素をハイライトしながら案内する |
| 操作待ちステップ | 「次へ」ボタンではなく、入力・クリック・キー操作・画面遷移が実際に行われたら次へ進む |
| 練習モード | 登録・送信などの操作を無効にする。本番環境でも安全に練習できる |
| ページをまたいだ再開 | 画面が切り替わっても、ツアーの続きから再開する |

デモとして、次のツアーを入れています（すべて実在のサイトで動きます）。

| ファイル | サイト | 内容 | 主に使っている機能 |
|---|---|---|---|
| `01-google-search-basic.json` | Google | 検索して結果を確認する | `input`、`navigate` |
| `02-google-search-practice.json` | Google | 検索操作の練習（練習モード） | `practice`、`blockRules`、`key` |
| `03-wikipedia-search.json` | Wikipedia 日本語版 | 記事を検索して読む | `input`、`key`（Enter で別の記事へ遷移）、`fallbacks` |
| `04-wikipedia-history.json` | Wikipedia 日本語版 | 記事の編集履歴を確認する | `navigate` の `query`、`pageQuery`（`?action=history` の画面） |
| `05-wikipedia-random.json` | Wikipedia 日本語版 | メインメニューから記事をおまかせ表示 | `click`、`skipIf`（メニューをサイドバーに固定していれば飛ばす） |
| `06-wikipedia-diff.json` | Wikipedia 日本語版 | 記事 → 履歴 → 差分（途中で閉じても、今いる画面から再開） | `navigate` の自動スキップ ＋ `skipIf`（下記） |

Wikipedia のツアーは、どの記事のページからでも開始できます（例: https://ja.wikipedia.org/wiki/東京都 ）。

---

## 入れ方

1. このフォルダを `git clone`（または zip を展開）する
2. Chrome で `chrome://extensions` を開く
3. 右上の「デベロッパーモード」をオンにする
4. 「パッケージ化されていない拡張機能を読み込む」で、**このフォルダ（manifest.json があるフォルダ）** を選ぶ
5. https://www.google.com/ を開くと、右下に「新人研修」ボタンが出る

## 更新したとき

ファイルを編集した、または `git pull` したら、`chrome://extensions` でこの拡張機能の **再読み込みボタン（↻）** を押し、対象のページも再読み込みします。
最新版になったかは、`chrome://extensions` に表示されるバージョン（`manifest.json` の `version`）で確認できます。

> 会社の Chrome がポリシーでデベロッパーモードを禁止している場合は、この方法では読み込めません。

## ガイドが多いとき

パネルの一覧は `panelMaxVisibleTours` 件分（初期値 2 件）の高さまでで、超える分はスクロールで表示します。
一覧の下の「すべて表示」を押すと、画面全体のダイアログで全ガイドを一覧できます。

- タイトルと説明文で検索して絞り込める
- Esc キー、右上の ×、ダイアログの外側のクリックで閉じる
- 「開始」を押すとダイアログが閉じ、そのガイドが始まる

## 完了記録について

ツアーを最後まで終えると、一覧に「完了済み」と表示されます。
この記録は拡張機能専用の保存領域（`chrome.storage.local`）にツアーの `id` で保存されるため、**閲覧履歴の削除では消えません**。

- **ツアーごとに消す**：一覧の「完了済み」の横にある「記録を消す」を押す
- **すべて消す**：拡張機能を削除して入れ直す（再読み込み ↻ では消えません）
- ツアーの `id` を変えると、別のツアーとして未完了の扱いになります

├── highlighter.js       ハイライトと吹き出しの表示（Driver.js）
├── navigation-watcher.js 操作の直後に画面遷移が始まったかを調べる
├── tour-engine.js       ステップの進行・ページ遷移の追従・練習モードの管理
├── url-watcher.js       URL の変化の検知
├── panel.js             右下のパネル
└── main.js              起動処理（部品を組み立てるだけ）

ファイルを追加したときは、`manifest.json` の `"js"` にも追記してください。

## 社内システムへの差し替え手順

### 1. 対象 URL を変える（`manifest.json`）

`"matches"` が **2か所**（`content_scripts` と `web_accessible_resources`）あるので、両方を書き換えます。

```json
"matches": ["https://erp.example.co.jp/*"]
```

### 2. 設定を変える（`site/config.js`）

```js
globalThis.GUIDE_SITE_CONFIG = {
  panelTitle: '受発注システム ガイド',
  panelMaxVisibleTours: 2,       // 一覧でスクロールせずに見せる件数（超えると「すべて表示」ボタンが出る）
  elementTimeoutMs: 15000,       // 表示が遅い画面では長めにする
  tourFiles: [
    'site/tours/01-order-entry.json',
    'site/tours/02-order-search.json',
  ],
  remoteToursUrl: null,
};
```

### 3. ツアーを書く（`site/tours/*.json`）

JSON ファイルを置いて、**`site/config.js` の `tourFiles` にファイル名を追記**します（追記しないと読み込まれません）。
ツアーの `id` は、ほかのツアーと重ならないようにしてください。重なった場合は後から読み込んだ方が外れ、パネルにエラーが表示されます。

> ツアーを何本追加しても、互いに影響することはありません。画面の要素を探したり、操作を監視・ブロックしたりするのは、
> 「開始」を押したツアーの、今表示しているステップの分だけです。同時に実行できるツアーは1つです。
ツアーの `match` に書いた URL が、`manifest.json` の `"matches"` にも含まれている必要があります。
書き間違いがあると、パネルに「読み込めなかったツアーがあります」と、どのファイルのどの項目が悪いかが表示されます（ほかのツアーは動き続けます）。

```json
{
  "id": "order-entry",
  "title": "受注登録の基本",
  "description": "得意先を選んで受注を登録するまで",
  "match": ["https://erp.example.co.jp/*"],
  "startPage": "/orders/new",
  "mode": "practice",
  "blockRules": [
    { "selector": "#btn-register", "events": ["click"], "message": "練習モードのため登録されません" }
  ],
  "steps": [
    {
      "id": "customer",
      "page": "/orders/new",
      "target": { "selector": "#customerCode", "fallbacks": ["input[name='customer_cd']"], "text": "得意先" },
      "title": "得意先コードを入力",
      "content": "得意先コード（8桁）を入力します。",
      "advance": { "type": "input", "pattern": "^\\d{8}$" }
    },
    {
      "id": "register",
      "page": "/orders/new",
      "target": { "selector": "#btn-register" },
      "title": "登録する",
      "content": "内容を確認したら「登録」を押します。",
      "advance": { "type": "click" }
    }
  ]
}
```

#### 主な項目

| 項目 | 説明 |
|---|---|
| `match` | ツアーを有効にする URL（`*` は任意の文字列） |
| `startPage` | 開始できる画面のパス。ほかの画面では「開始」ボタンが押せない |
| `startQuery` | 開始できる画面のクエリ（URL の `?` 以降）。例: `{ "screen": "menu" }` |
| `mode` | `guide`（通常）または `practice`（練習モード） |
| `blockRules` | 練習モードで無効にする操作。`events` は `click` / `submit` / `key:Enter` など |
| `steps[].page` | そのステップを表示する画面のパス。**画面ごとに必ず書く**（ページ遷移後の再開に使う） |
| `steps[].pageQuery` | そのステップを表示する画面のクエリ。`?` 以降で画面が切り替わるシステム向け |
| `steps[].skipIf` | 条件を満たしていたら、このステップを飛ばす（下記） |
| `steps[].target` | ハイライトする要素（下記）。省略すると画面中央に吹き出しだけを出す |
| `steps[].content` | 説明文。`<b>` や `<br>` が使える |
| `steps[].advance` | 次へ進む条件（下の表）。省略時は `next` |

| `advance.type` | 次へ進むタイミング | 追加の項目 |
|---|---|---|
| `next` | 吹き出しの「次へ」を押したとき | — |
| `click` | 対象をクリックしたとき | `selector`（別の要素で判定したい場合） |
| `input` | 対象に入力したとき | `minLength`、`pattern`（正規表現） |
| `key` | 対象でキーを押したとき | `key`（例: `"Enter"`） |
| `navigate` | 画面のパス・クエリが一致したとき。**すでに一致していればステップを飛ばす** | `path`（例: `"/orders/*/done"`）、`query`（例: `{ "screen": "order" }`）。少なくとも一方 |

練習モードでブロックされた操作も「操作した」とみなし、次のステップへ進みます。

`click` / `key` で次へ進むときは、その操作で画面遷移が始まるかを約0.4秒だけ確かめてから次のステップを表示します。
遷移が始まった場合は、元の画面には何も出さず、新しい画面で表示します（遷移前の画面に次の吹き出しが一瞬出ることを防ぐため）。

#### URL の `?` 以降で画面が切り替わるシステム

`main.exe?screen=order` のように、同じアドレスで `?` 以降だけが変わるシステムでは、パスに加えてクエリで画面を指定します。

```json
{
  "id": "open-order",
  "page": "/cgi-bin/main.exe",
  "pageQuery": { "screen": "menu" },
  "target": { "selector": "a", "text": "受注入力" },
  "title": "受注入力画面を開く",
  "content": "メニューの「受注入力」をクリックします。",
  "advance": { "type": "navigate", "path": "/cgi-bin/main.exe", "query": { "screen": "order" } }
}
```

- クエリは書いたキーだけを比較します。`{ "screen": "order" }` は `?screen=order&id=5` にも一致します
- 値には `*` が使えます。`{ "id": "*" }` は「`id` があれば値は何でもよい」という意味です
- `page` の中に `?` を書いても、クエリとしては扱われません（`?` は「任意の1文字」の意味になります）

#### `skipIf`（もう済んでいる操作を飛ばす）

ステップを表示する前に条件を確認し、**書いた条件をすべて満たしていれば**、そのステップを飛ばして次へ進みます。

| 条件 | 意味 |
|---|---|
| `"page": "/orders/new"` | その画面（パス）にいる |
| `"query": { "tab": "detail" }` | URL の `?` 以降が一致する |
| `"exists": "#tab-detail.active"` | その要素が画面に表示されている（`{ "selector": "button", "text": "明細" }` の形でも書ける） |

例：「明細」タブがすでに開いていたら、「明細タブを開く」ステップを飛ばす

```json
{
  "id": "open-detail",
  "page": "/cgi-bin/main.exe",
  "pageQuery": { "screen": "order" },
  "target": { "selector": "button", "text": "明細" },
  "title": "明細タブを開く",
  "content": "「明細」タブをクリックします。",
  "advance": { "type": "click" },
  "skipIf": { "exists": "#tab-detail.active" }
}
```

条件は、ステップを表示しようとした時点で1回だけ確認します。表示されたあとに条件を満たしても、自動では進みません。

#### 途中で閉じても、今いる画面から再開できるガイドの書き方

複数の画面にまたがるガイドを途中で × で閉じ、別の日に「開始」し直すと、通常は1ステップ目から判定されます。
次の2つを組み合わせると、**今いる画面を見て、それより前のステップを自動で飛ばし**、その画面のステップから始まります。

1. 画面を移るステップは `navigate` で書く（遷移先にすでにいれば、そのステップは飛ばされる）
2. それより手前のステップには、`skipIf` で「もっと先の画面にいたら飛ばす」と書く

`06-wikipedia-diff.json` の構成:

| ステップ | 表示する画面 | 飛ばす仕組み |
|---|---|---|
| ① 履歴を開く | 記事 | `navigate`（履歴の画面にいたら飛ばす）＋ `skipIf`（差分の画面にいたら飛ばす） |
| ② 版の一覧 | 履歴 | `skipIf`（差分の画面にいたら飛ばす） |
| ③ 差分を開く | 履歴 | `navigate`（差分の画面にいたら飛ばす） |
| ④〜⑥ 差分の説明 | 差分 | — |

記事の画面で開始すると①から、履歴の画面なら②から、差分の画面なら④から始まります。
`startPage` は書かないでください（書くと、その画面以外では「開始」ボタンが押せなくなります）。

#### `target` の書き方

| 書き方 | 意味 |
|---|---|
| `{ "selector": "#login" }` | セレクタに一致する要素 |
| `{ "selector": "button", "text": "Log in" }` | セレクタに一致し、**その文字を含む**要素（「Log in」と書かれたボタン） |
| `{ "text": "Log in" }` | その文字を含むボタン・リンクなど |
| `{ "selector": "#login", "fallbacks": ["a[href='/enter']"] }` | 第一候補が見つからなければ予備を試す |

`"selector": "button"` だけだと、画面で**最初に見つかったボタン**になります。ボタンが複数ある画面では `text` を併用してください。

> クリックで次に進めたいステップには `"advance": { "type": "click" }` を書いてください。
> 書かない場合は「次へ」ボタンで進む扱いになり、要素をクリックしても進みません。

### 4. セレクタの選び方（壊れにくくするコツ）

1. `id` や `name` 属性を使う（`#customerCode`、`input[name='customer_cd']`）
2. 次に `data-*` 属性や `aria-label`
3. 見た目用のクラス名は避ける（デザイン変更ですぐ変わる）
4. 自動生成された ID（`ti6dpd`、`ext-gen123` など）は使わない

`fallbacks` と `text` を書いておくと、第一候補が壊れても動き続けます。
予備の手段で見つかったときは、開発者ツールのコンソールに `fallback-used` と出るので、セレクタを直す目安になります。

### 5. 実際のサイトで分かった注意点

Wikipedia の例を作ったときに見つかった点です。業務システムでも同じことが起きやすいので参考にしてください。

- **クリックすると作り直される要素がある**：Wikipedia の検索欄は、クリックした瞬間に別の入力欄に置き換わり、`id` もなくなります。
  拡張は、対象の要素が消えたら自動で探し直してハイライトし直しますが、**置き換わる前と後の両方に一致するセレクタ**を書いてください
  （例: `#searchInput` ではなく `#searchform input[name='search']`）。
- **見た目のボタンと、実際にクリックされる要素が違うことがある**：Wikipedia のメニューボタンは、透明なチェックボックスが上に重なっています。
  クリックで進まないときは、開発者ツールでクリックした位置の要素を確認してください。
- **`text` は画面の文字と一部でも違うと一致しない**：思い込みで書かず、実際の表示をコピーするか、短めの文字（例: 「版を比較」）にしてください。
- **開いたメニュー（ドロップダウン）は、パネルなど別の場所をクリックすると閉じる**：「メニューが開いていたら飛ばす」という `skipIf` は、
  パネルの「開始」を押した時点でメニューが閉じるため働きません。常に表示されている状態（サイドバーに固定など）を条件にしてください。

### 6. （任意）ツアーを社内サーバーから配信する

拡張機能を配り直さずにツアーを更新したい場合は、`site/config.js` の `remoteToursUrl` に、ツアー定義の JSON 配列を返す URL を設定します。
あわせて `manifest.json` に `"host_permissions": ["https://そのサーバー/*"]` を追加してください。

## 既知の制限

- iframe の中の要素には未対応です
- ハイライトは `target` で指定した要素そのものに付きます。外枠ごと強調したい場合は親要素のセレクタを指定してください
- デモの Google 用セレクタは、Google 側の変更で動かなくなることがあります
